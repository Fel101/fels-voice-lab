# 1.0.1 in detail

Every change in 1.0.1, with what it does and how it was checked. The [changelog](../../CHANGELOG.md) has the short
version, which is also the release's notes.

## Updating from 1.0.0

- **Update now** on **System & backups**, `update.bat`, or the new Setup.exe over the Lab updates 1.0.0 to 1.0.1.
  `update.bat --undo` puts 1.0.0 back after an update made by **Update now** or `update.bat`.
- **The library opens as it was.** The Cast database gains one column, `release_expires`, for a recording's permission
  end date. It stays schema 9, so 1.0.0 can still open the library after an undo (it ignores the column). On the first
  start, the Lab fills the column for recordings imported from Voice Slate from the copy of the clip's details it kept
  beside each one, when that copy still matches the recording, and recordings made from those (edits, and recordings
  saved from takes) get the same date.
- No model's pinned packages or files changed, so no model needs installing again.

## A speaker's permission can end

Voice Slate keeps a speaker's signed release, with an optional end date. A kept clip's details carry that date.

- The import preview, for a file or a clip in the inbox, and **Edit voice** show "Permission valid through <date>", or "Permission expired on
  <date>" once it has passed. The date is the last day the permission covers, in this computer's time, as in Voice
  Slate.
- An expired clip can still be imported and reviewed. Approving it, or choosing it as the voice's recording, is refused
  with what to do: record the renewed release in Voice Slate, keep a clip with it, then import and approve that clip in
  Cast. A clip with a new end date is a new version of the recording, even when its audio is the same.
- New speech is refused after the date: a take, a voice-to-voice conversion, a scene line or batch, an audiobook, the
  automation tools and `POST /api/speak` all check it before they start, and the model worker checks again before it
  loads the recording.
- What was made stays. Recordings, takes and their audio, and saved scenes open and can be edited; a scene line with an
  expired voice is refused only when you render it, and its other lines still render. A portable project still exports,
  and carries the date, so the Lab that imports it enforces it too.
- `GET /api/voices` lists such a voice as not ready, with the reason, so NPC Forge and Altera do not choose it.

## Speakers keep their names

Voice Slate 1.0.1 adds the speaker's current name, in any script, to the copy of the clip's details in the file it sends
(`speaker_display_name`). The inbox, the import preview and the suggested character name use it. A clip from Voice Slate
1.0.0 has no display name, and the Lab uses the speaker's folder name, as before.

## The first screen

With no model installed, the first screen offers Kokoro 82M for the CPU, with its download size, and, on a PC that can
take its GPU build, Kokoro for the GPU with its size. After the install, it leads into the sample scene as before.

## Fixed

- A voice cloned from a recording, such as a Voice Slate clip, says **Made from a recording** in **Cast library**, not
  "Created with Source model not recorded".
- A voice designed from words says what its model's licence allows and that no person's recording is in it, not
  "Unknown; review checkpoint terms and reference rights".
- A model's install could stop with "Access is denied" when Windows or a virus scanner held its progress file. The
  installer now tries again for up to three seconds, with waits that grow and vary.
- `tools/real_model_smoke.py` prints its table on a Windows console that cannot show a model's own progress bars.
- Links to Altera use its new address, github.com/Fel101/fels-altera.

## For scripts and the other apps

- `GET /api/voices`: `made_from` is `recording` for a voice cloned from a recording, `words` for one designed from words
  (also when its recording was made from one of its takes), and `model` for one of a model's own voices. A cast voice
  whose speaker's permission has ended has `ready: false` and the reason in `why_not`.
- `POST /api/cast/slate-clip/preview` and the import answers' `clip` carry `speaker_display_name`, `release_expires`
  and `release_expired`. The import answers now include `clip`.
- `GET /api/engines/status`: Kokoro, when not installed, also has `install_variants` with `cpu` and `gpu` download
  estimates.

## For contributors

- The bug report is a form, like the other Fel's Studio apps', and asks for the Lab's own report.
- CONTRIBUTING says to run the CPU smoke pass where the models have PyTorch's ordinary CPU or CUDA build.
