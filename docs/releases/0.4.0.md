# 0.4.0 in detail

Every change in 0.4.0, with what it does and how it was checked. The [changelog](../../CHANGELOG.md) has the short
version, which is also the release's notes.

0.4.0 is one large update with three aims: anyone can use the Lab, other apps can use its voices, and the people who use
it can say what they need. The Lab sends nothing about its users, and that has not changed.

## Updating from 0.3.0

- **Run the new Setup.exe.** 0.3.0 has no **Update now**, so download `FelsVoiceLab-Setup-0.4.0.exe` and run it over the
  Lab. It says it will update 0.3.0 to 0.4.0, refuses to put an older version over a newer one, and asks you to close the
  Lab first. It removes the files 0.4.0 dropped, but leaves any you changed. It brings the core and desktop packages up to
  date from the packages it carries, then opens the Lab. `update.bat` from a 0.3.0 folder works too.
- **The library opens as it was.** No model needs installing again: no model's pinned packages or files changed.
- **Going back.** `update.bat --undo` puts 0.3.0 back after an update made by `update.bat`. It refuses an update made by
  Setup.exe and says how to go back. 0.3.0 opens a 0.4.0 library. It keeps timed scenes, sections and dub settings, and
  ignores recipes, which are in a database of their own (`data\automation`).
- **Backups.** A backup made by 0.4.0 is format 2. 0.4.0 restores 0.3.0's backups, but 0.3.0 refuses a format 2 backup
  and says to update.

## Connecting other apps

- **One known address.** The Lab's window listens on `127.0.0.1:8765`, the same as `serve.bat` and `serve.py`. When
  another program has that port, the Lab takes a free one and says why. **Port for the Lab's window** on **System &
  backups** changes it, or 0 picks any free port. Opening the window while `serve.bat` runs the same Lab opens that
  service's page, and closing the window leaves it running. Starting `serve.bat` twice says the Lab is already running.
  If the service the window opened on stops, the window closes and says so.
- **The address file.** A running Lab writes its address to `%LOCALAPPDATA%\FelsVoiceLabService\service.json`.
  `lab_cli.py` looks at `--url`, `VOICE_LAB_URL`, that file and then 8765, and says plainly when the Lab is not running.
  `GET /api/health` also answers `app` and `lab_id`.
- **Connect other apps** on **System & backups** shows the address, Copy buttons, a command that tests it, the line that
  adds the Lab to Claude Code with this computer's paths, the `mcpServers` settings for other MCP apps, and the address
  for apps that use OpenAI's speech API. [Connecting other apps](../CONNECT.md) is the guide.
- **An MCP server.** `tools/mcp_server.py` gives Claude Code and other MCP apps the Lab's voices with nine tools:
  - `lab_status` and `list_voices`;
  - `speak`, which plays aloud by default, takes up to 10,000 characters and keeps no take;
  - `stop_speaking`;
  - `set_voice` (each connection keeps its own) and `describe_voice`;
  - `transcribe`;
  - `preview_voice_candidate` and `import_voice_candidate` for a Voice Slate recording.

  It speaks MCP 2026-07-28 and the initialize handshake of 2025-11-25 and earlier. When the Lab is closed it starts the Lab's service, which stops
  again with the app. An HTTP mode on `127.0.0.1` asks for a token kept in a private file. Clips spoken for other apps go
  to `out\spoken\`, and cleanup removes them a day after the app stopped. `docs/examples` has an n8n example.
- **OpenAI's speech API.** Apps that can point OpenAI's speech API at another server, such as Open WebUI, speak with the
  Lab's voices: base address `http://127.0.0.1:8765/v1`, any key, and a voice's name from the Lab. The routes are
  `POST /v1/audio/speech`, `GET /v1/models`, `GET /v1/audio/models` and `GET /v1/audio/voices`. MP3 (the default), Opus
  and AAC need FFmpeg, and without it the answer is 503 `ffmpeg_not_installed`. WAV, FLAC and 24 kHz PCM need nothing.
  `speed` works with Kokoro (0.5 to 2.0), and `instructions` go to voices that take an acting direction. Errors on `/v1/`
  routes take OpenAI's shape.
- **Speaking for callers.**
  - `/api/speak` and `/api/performance` take up to 10,000 characters. Longer text is split as Scenes splits it, spoken
    part by part and joined into one WAV (`X-Parts`), and it can be cancelled between parts. A voice invented from a
    description is refused for text that needs more than one part.
  - `GET /api/voices` lists the voices that can speak now: Cast voices, and the preset voices of installed models. Each
    has a name to send back, its model, its languages, whether it takes an acting direction, and whether it is ready and
    why not. `/api/speak` takes that name as `voice`.
  - `/api/performance` with `keep_take: false` speaks as a Cast voice and keeps no take, and the clip is still labelled as
    AI-generated. The voice's name may replace `identity_id`, and `line_id` is needed only when the take is kept.
  - `lab_cli.py` has `voices`, `--play` for `speak` and `perform`, and `--no-keep` for `perform`.
- **Error codes.** Every error answer carries a `code` beside its sentence: `invalid_request`, `not_local`, `not_found`,
  `busy`, `already_exists`, `conflict`, `too_large`, `cancelled`, `failed`, `upstream_failed`, `model_not_installed`,
  `ffmpeg_not_installed` and `timeout`. A model that is not installed answers 503 `model_not_installed`, where 0.3.0
  answered 500 with no code.
- **The network.** The Lab still answers only this computer, so an app in a container or on another computer cannot
  reach it. Listening on the network needs a key and a setting that is off until someone turns it on; that is an issue
  for a later release. [Security](../../SECURITY.md) says what other programs on this computer can reach.

Checked with the real models in a scratch Lab:
- 5,000 characters spoken in five parts, in order;
- a Cast voice by its name with no take kept;
- a 503 with its code for a model that was not installed;
- through the MCP server, a whole conversation, stopping while it made a clip and while it played, and the Lab started
  and stopped by the server, with the official MCP Python SDK 2.3.0 in both eras;
- with the official `openai` Python package, a Cast voice as WAV and MP3 and a Kokoro voice as Opus at speed 1.3, each
  file labelled as AI-generated speech, and 404 for an unknown voice.

## Updating the Lab

- **Update now** on **System & backups**, and in the header when a newer release is out. It shows the plan first. Then
  the Lab closes, updates in a window of its own and opens again. After an update the page says once what changed, with
  **Install** buttons for any model to install again. **Open the Lab's folder** is on **System & backups** too.
- **Setup.exe over an older install** is an update, as described under [Updating from 0.3.0](#updating-from-030). It
  says on its last page, and the Lab says too, which models need installing again.
- `update.py --finish` also writes `out\update\notice.json` for the page, so `update.bat` shows the note too.
  `serve.bat` runs as one block, so an update can replace it while it waits, and its console says why the Lab closed.

## Home, empty pages and the sample scene

- **Home** opens first, with the five things worked on most recently, newest first. A subtitle dub is one item. Each
  opens in its workspace.
- **An empty library** shows only ways to start. Cast, Perform and Compare each say what to do first. Scenes has one
  **Import a script** that takes a file or pasted text.
- A scene's batch controls and players show only when it has a batch or a built mix. Reopening a scene brings its built
  mix back.
- **The sample scene.** Once Kokoro is installed, the first-run note, Home, an empty Cast and an empty Scenes offer **Open
  the sample scene**: two characters with Kokoro's preset voices and a nine-line scene, ready to render. It is made only
  when asked. **Remove the sample…** says what it deletes and asks first: the scene with its batches and previews, its
  characters, their voices and every take made with them. Copies in export packages stay.

## Choosing a model

- Each card in **Models & features** says in plain words whether the model runs without a graphics card, or how much
  graphics memory it needs. It also says whether it clones a voice, has preset voices or designs one from a
  description, whether it takes acting directions, its languages, and what its audio may be used for ("not stated" where
  nothing says). Kokoro 82M is marked as a good first model.
- **Which model fits?** above the cards: no graphics card, cloning a voice from a recording, and a language. The cards
  that do not fit are hidden, and a line names the ones left.
- **Uninstall…** on an installed model's card shows what it would delete, and what stays because another model uses it,
  then deletes only when asked.
- "Integrated" moved under a card's **Details**, with what the language screen heard in each language.

Checked: every card's facts against [capabilities and limits](../../MODEL_CAPABILITIES.md), read by the owner.

## Stories and audiobooks

- **Narrate a document.** **Stories & audiobooks** reads a `.txt` or `.md` manuscript, with one voice or several. Each
  chapter becomes a scene that you can edit and render in **Scenes & batch**. Export writes WAV, FLAC, MP3 and M4B with
  chapter marks, plus a cue sheet and captions, and measures the whole book's loudness.
- A book can have up to 6,000 passages and 160 chapters. Project pronunciations are written `word = how to say it`.
- A text heading such as "Chapter 1 The Harbor" is a heading, and a one-line paragraph such as "Part two of the plan was
  simple." is spoken.

## Subtitles and timed scenes

- **Import subtitles.** An SRT or WebVTT file becomes a timed scene: a voice for each speaker, the cue times kept, and
  each take placed on its cue. A take that runs long is marked, not cut.
- A subtitle file longer than 30 minutes or 500 cues becomes numbered sections, each saying where it starts in the
  video. Sections stay in order in Scenes, Projects and the recipe scene picker.
- Cues can be edited, split and merged. Captions go out on the original times.

## Dubbing

- **Dub media** in **Scenes & batch**: attach a video or audio file, edit the target wording, and review the picture.
- **Speed up to fit** on a line that runs over its cue makes it faster, at most 1.35×, and the dub's mixed audio uses the
  faster line.
- Export writes the audio and the captions, and an MP4 with the original sound as a second track.
- Subtitles can be drafted from the audio with speech recognition. A dub's language list names languages, those the
  line's voices speak first.
- A portable dub can carry its source video and background.

## Projects and voice files

- **Projects** finds scenes, timed scenes and books, and moves a checked copy to another library.
- **Export this voice** on an approved Cast card writes a voice file. A voice made from a person's recording asks for
  permission first. A voice you import arrives as a candidate, and the import shows its origin and allowed use first. A
  file with one byte changed is refused.

Checked: a Kokoro voice and a Chatterbox Turbo voice made from a Kokoro take, exported from one Lab and imported into
another, gave the same audition, with Kokoro's audio correlating at 0.996.

## Automation

- **Recipes** chain steps: speak, transcribe, translate, master, convert and dub. Each saved recipe can be previewed and
  run, and its runs and their audio are kept.
- **A dubbing queue** with watch folders.
- **Outside providers** are optional profiles. A provider's key lasts until the Lab closes. Before a recipe that uses one
  runs, the Lab shows each destination and the fields it would send, and sends nothing until you approve.
- **Convert voice** in a recipe offers the approved voices that have a recording, by name.

## Speech recognition

- **Install speech recognition** on **System & backups** installs Whisper Tiny and Small, checked by hash. Transcripts
  are drafted on your computer.
- `POST /v1/audio/transcriptions` and `POST /v1/audio/translations` (speech to English), and short live sessions under
  `/api/live`.
- **Import from Voice Slate** in Cast makes a candidate from a recording kept by the companion recorder.

## Audio tools

- Repeatable sound effects.
- **Master** a WAV or FLAC file to a target loudness, into a separate file. The target and the gain go into the file's
  receipt.
- Mastering and scene deliveries can write 16-bit PCM, 24-bit PCM or floating-point WAV.

## Page language

- **Page language** beside **Theme**, on the main page and on Compare. Changing it reloads the page, so save your work
  first. 0.3.0 ignores the saved choice.
- **Spanish** is a draft, marked "borrador, sin revisar por un hablante" (draft, not yet checked by a speaker) until
  someone who speaks Spanish has read it. The picker lists each language in its own words on every page.
- Model tags stay as the models need them, such as `[laugh]`, `[voice:Mira]` and `<|speaker:0|>`. Language names in
  lists, dates, counts and lists of names follow the page language. Dates follow the browser's region when it matches
  the page language, so an English reader in the UK sees British dates.
- These stay in English in 0.4.0: model card facts, voice descriptions, the service's messages beyond the common error
  codes, and the diagnostics report. The browser's own file and audio controls follow the browser's language.
- A broken translation file does not stop the Lab. It offers English, writes one line to the service log, and keeps the
  saved choice, so fixing the file brings the language back.
- [Translate the Lab](../../CONTRIBUTING.md#translate-the-lab) says how to add a language.

Checked: the English page, captured on every workspace and on Compare with every fold-out open, is the same as before
apart from the sentences meant to change. Kokoro spoke a clip and a Perform take through the Spanish page.

## Hearing from you

- **Tell us what you need** on **System & backups** opens the Discussions page. The Lab sends nothing itself.
- A feature request form on GitHub asks first what you are making.
- The report you can copy counts dubs, narrations, projects, audio tool files and recipes. It says whether a connection,
  a provider profile and speech recognition are set up, but never their addresses or keys. A test fills a library with a
  character's name, a voice's name, a transcript and a path in the home folder, and finds none of them in the report.

## Backups

- Backups hold recipes and their runs. Attached dub media and deliveries, and Audio tools files, are optional sections.
  Voice and project files join the export section.
- Backups are format 2. See [Updating from 0.3.0](#updating-from-030).

## Fixes

- A Kokoro line of about 1,200 characters failed with "Worker protocol message exceeds 65536 bytes". The limit is now
  1 MiB.
- An edit made just after **Save** in Scenes could be replaced when the page reloaded the scene. The page now keeps an
  edit made since the save.
- `[softly] MIRA: Did you?` in a plain-text script is Mira's line with the direction "softly", not narration.
- Two Lab services could listen on the same port on Windows, because Python's server let them share it.
- A "not found" answer's sentence came wrapped in quotes.
- The scene batch runner could stop for the rest of the session if a job disappeared just as it started.
- A deleted scene's folder could come back when one of its batches finished at the same moment.
- The install window's buttons, and the first-run note's, work as soon as the page loads.
- When a Kokoro voice, or Kokoro itself, is missing, the message says what to do.
- `serve.bat` uses port 8765, as everything else does. It used 8768.

## For contributors

- **A staged release.** The release workflow makes the release as a draft. A check job downloads Setup.exe and
  `SHA256SUMS` from the draft, checks the names, the hash and the attestation (`tools/check_release_files.py`), and
  installs that Setup.exe over the release before it (`tools/check_setup_update.ps1`). Only then is the draft published,
  and it is marked latest only when it is the newest version.
- Setup.exe carries the file lists of every release tag up to its version, so building it needs the tags. The
  workflows check out the whole history.
- The checks on GitHub run every Node test file. The workflows use the actions' Node 24 versions.
- The page's words are in `locales/en.json`, and a test checks that every key used exists, that no translation has a
  key or a value place English lacks, that model tags are kept, and that no English is passed into a message.
- The browser tests' servers have the Lab's listen queue of 128, as does the MCP HTTP server.
